## 1. 产品概述

一个纯本地的 Todo 浏览器扩展，点击图标在标签页打开；可选接管浏览器空白新标签页。

**名字**：Just Todo —— 只做待办。分组、勾选、归档、搜索四件事做到顺手为止，不堆项目管理 / 协作 / 看板那类复杂功能（非目标见下）。
对外显示名（`extName`，中英统一为 `Just Todo`）用于商店、扩展管理页与工具栏提示；内部标识保持 `todo-just`（npm 包名、`scripts/package.py` 的 zip 前缀、gecko id `todo-just@local.extension`）—— 它们不出现在用户可见处，且改 gecko id 会变成另一个附加组件身份。

**搜索**：商店没有独立的关键词字段，能被检索的文本就是 `extName`（≤75 字符）与 `extDescription`（≤132 字符），因此两者都显式包含 `Todo` 这个关键词（`tests/i18n.test.ts` 会同时守住长度上限与关键词，超长会导致扩展加载失败）。名称里关键词的位置不决定"能否被搜到"（匹配按词切分），真正决定排名的是安装量、评分与留存，那些不是靠名字能优化的。

**核心功能（交互细节以预览稿为准）：**

- 任务增删改；状态：待办 ⇄ 已完成 → 归档
- 任务卡片自上而下：分组 Tab → **常驻新增行**（回车新增；「全部」标签下右侧可选分组，其他标签下显示当前分组名）→ 待办列表 → **已完成分隔行**（`已完成 N` ＋ 右侧「全部归档 (N)」按钮）→ 已完成列表（勾选即删除线置灰沉底，再点可恢复；**两个列表都可拖拽调整顺序**，限同列表内）
- 下部：归档区，默认显示最近 N 条，搜索覆盖**全部**归档；归档可恢复为待办、彻底删除
- 分组管理：新增 / 双击重命名 / 删除（活跃任务变「未分组」；**归档任务永久保留归档时的分组名**）
- 设置：三套主题、语言、归档显示条数、自动归档、新标签页接管开关、容量上限

**非目标（V1 不做）：**

- 云同步、账号体系、任务备注/截止日期/优先级/标签、提醒通知、弹窗 Popup 形态

## 2. 入口与信息架构

两个 HTML 页面入口 + 一个 background，**共用同一份 Todo 应用代码**：

```
┌────────────────────────────────────────────────────────────┐
│  manifest（静态声明）                                        │
│  · action（无 default_popup）                                │
│  · permissions: storage + tabs（用于识别新标签页）           │
│  · 不声明 chrome_url_overrides（第 11 节：运行时重定向）     │
└────────────────────────────────────────────────────────────┘
        │ 点击图标                        │ 打开新标签页
        ▼                                 ▼
 background.ts（tabs 事件重定向）   newtab.html / newtab.ts（重定向落点）
 chrome.action.onClicked          newtab.html 恒渲染 Todo（无视图分流）
   ├─ 已存在 app 标签页 → 激活它      ├─ mountApp()（与独立页完全相同）
   └─ 否则 chrome.tabs.create        └─ 设置变化由 mountApp 内部 storage.onChanged 处理
        (app.html)
                                        （开关只决定要不要重定向过来）
        ▼
 app.html / app.ts（独立全页面）
   mountApp()：加载设置 → 初始化 i18n/主题 → 渲染整个 Todo 界面
   app.html#settings 可直接深链到设置弹层
```

**为什么 newtab 不用静态覆盖、而要重定向**：见第 11 节（浏览器限制与代价）。

## 5. manifest 与多浏览器策略

由 `scripts/manifest.mjs` 一份公共配置 + 目标覆盖生成，**Chrome 与 Edge 共用同一份 MV3 产物**（Edge 可直接加载/上架 Chromium 包），Firefox 为 MV2。

| 项 | MV3（Chrome / Edge） | MV2（Firefox ≥128） |
|---|---|---|
| manifest_version | 3 | 2 |
| 点击图标 | `action: {}`（不设 popup → 触发 onClicked） | `browser_action: {}` |
| 接管新标签页 | 不声明覆盖，`background.ts` 运行时重定向 | 同机制（`about:newtab` / `about:home` 一并识别） |
| 后台 | `background.service_worker` | `background.scripts` + `persistent: false` |
| 权限 | `["storage", "tabs"]` | 同 |
| 其他 | `minimum_chrome_version: "111"` | `browser_specific_settings.gecko`（id + strict_min_version 128） |
| content_scripts / host_permissions / web_accessible_resources | **均不需要** | 同 |

**唯一的 API 兼容点**（封装在 `shared/action-compat.ts`）：

```ts
const nav = chrome.action ?? (chrome as any).browserAction;
nav.onClicked.addListener(() => openOrFocusApp());
```

**打开/激活逻辑（background.ts）**：先 `chrome.tabs.query` 查找已打开的 `app.html`，找到则切换到该标签页（必要时切窗口），否则 `chrome.tabs.create`。

**构建命令与产物**（照搬参考项目）：

```
npm run build          # → output/MV3   （Chrome/Edge 加载此目录）
npm run build:firefox  # → output/MV2   （Firefox 加载此目录）
npm run watch
npm run check          # typecheck + 测试 + 双构建
npm run package        # 生成 dist/todo-just-{version}-{MV3,MV2}.zip，含违禁文件检查
```

## 6. 数据模型与持久化

### 6.1 存储布局（chrome.storage.local）

```
todo:settings:v1 → TodoSettings
todo:data:v1     → { version: 1, groups: Group[], tasks: Task[], archived: ArchivedTask[] }
todo:ui:v1       → { currentGroup: 'all' | string, newTaskGroup: string }   // 界面位置，见 6.3
```

单 key 存放全部业务数据，写入走「全量覆盖」（数据量有上限，见 6.4）；`version` 字段供未来迁移，store 内预留 `migrate()` 钩子。

`todo:ui:v1` 单独一份（`shared/ui-state.ts`），因为它不是"设置项"（设置面板里没有对应控件），而且**只在页面首次加载时读一次**：跨标签页同步不该把当前页面的 Tab 拽到别的页面刚切过去的位置。

### 6.2 类型定义

```ts
interface Group {
  id: string;                 // 生成规则：g_<时间戳>_<随机串>
  name: string;
  createdAt: number;
}

interface Task {              // 活跃任务（待办 + 已完成）
  id: string;
  title: string;
  done: boolean;
  gid: string | null;         // null = 未分组；分组被删时置 null
  createdAt: number;
  completedAt: number | null;
  order: number;              // 列表内排序键，拖拽重排写入（见 6.3 排序）
}

interface ArchivedTask {
  id: string;
  title: string;
  gid: string | null;         // 归档瞬间的分组 id（之后分组被删也不动）
  groupName: string | null;   // ★ 归档瞬间的分组名快照，永久保留
  archivedAt: number;
}

interface TodoSettings {
  locale: 'auto' | 'zh_CN' | 'en';
  theme: 'auto' | 'soft' | 'minimal' | 'dark';  // auto 的解析见第 7 节
  autoArchive: boolean;       // 勾选完成直接进归档（默认 false）
  archiveVisible: number;     // 归档区默认显示条数（默认 10）
  newtabOverride: boolean;    // 是否接管新标签页（默认 true）
  newTaskPosition: 'first' | 'last';  // 新建/恢复归档的任务插到最前还是最后（默认 last）
  activeLimit: number;        // 活跃任务容量上限（默认 50）
  archiveLimit: number;       // 归档容量上限（默认 100）
}
```

### 6.3 关键行为（对应需求第 5 点）

- **归档**：写入 `archived` 前从 groups 查当时名称写入 `groupName`；归档项**永不引用分组表**。
  - 之后分组被删除/改名 → 归档项仍显示归档时的组名（分组改名是否同步到旧归档：**不联动**，保持时间点语义，可预测）
  - 未分组任务归档 → `gid=null, groupName=null`，UI 显示「未分组」
  - 归档搜索同时匹配标题与 `groupName` 快照
- **删除分组**：该组活跃任务 `gid → null`；归档数据完全不动
- **排序**：待办与已完成各自按 `order` 升序；`order` 由**拖拽重排**写入（`moveTask`，只允许在同一列表内重排，重排后该列表重新编号为 0..n-1）
  - 新建任务 → 由设置项 `newTaskPosition` 决定：`last`（默认）追加到待办末尾、`first` 插到最前；勾选完成 → 已完成**最前**（最新完成在最上面，与旧版一致）；取消完成 → 回到待办末尾
  - 旧数据没有 `order`：待办回落到 `createdAt` 升序、已完成回落到 `completedAt` 倒序，升级后视觉顺序不变
  - 归档仍按 `archivedAt` 倒序，不参与拖拽
- **恢复归档**：任务回到活跃区为待办，插入位置同样跟随 `newTaskPosition`；若原分组已不存在则为未分组（`gid=null`）
- **界面位置**：停留的分组 Tab（`currentGroup`）、「全部」标签下新建行的分组选择（`newTaskGroup`）、归档区展开态（`archiveOpen`，默认折叠）存进 `todo:ui:v1`，刷新/重开新标签页后回到原处；读取时用 `reconcileUiState()` 校验分组是否还在，已删除则回落 `all` / 未分组
- **设置变更**：store 保存后派发 `storage.onChanged`，已打开的 newtab/app 页面自动刷新（跨标签页实时一致）；`todo:ui:v1` 的变化**不触发**刷新（否则两个页面会互相拽 Tab）

### 6.4 容量上限（对应需求第 4 点）

| 设置 | 默认值 | 范围 | 超限行为 |
|---|---|---|---|
| activeLimit 活跃任务上限 | **50** | 20–1000 | 新增被阻止，输入框提示「已达上限（N），请先完成或归档」；**不裁剪已有任务**，调小上限也不会删数据 |
| archiveLimit 归档容量上限 | **100** | 50–5000 | 归档写入后自动**静默淘汰最旧**，归档区底部显示「仅保留最近 N 条归档」提示 |
| archiveVisible 默认显示条数 | **10** | 1–100 | 仅影响展示，不删数据；搜索始终覆盖全部 |

- **调小 archiveLimit 要刷新页面才裁剪**：设置面板里改完只存值，不碰数据（手滑输入不该等于删归档）；页面加载时由 `mountApp` 调 `trimArchive` 落地并提示一次。归档写入时的淘汰照旧立即生效
- 上限校验与 clamp 集中在 `settings.ts`（照搬参考项目「storage 可能是脏数据」的防御式 load）
- 默认值是建议值，**最终由你确认**（见第 12 节）

### 6.5 测试（scripts/test-store.mjs，node 运行）

归档快照正确性、删除分组不影响归档、归档淘汰顺序、恢复归档时原组已不存在、上限阻止新增、排序、设置 clamp。

## 7. 主题系统（对应需求第 1 点）

三套已确认预览 + 一个「跟随系统」选项，共 4 个主题设置值：

| id | 名称（zh_CN） | 说明 |
|---|---|---|
| auto | 跟随系统（**默认**） | 浅色系统 → soft；深色系统 → dark。监听系统外观变化实时切换 |
| soft | 柔和明亮 | 蓝紫渐变 + 大圆角卡片（预览方案 A） |
| minimal | 极简专业 | Linear/Notion 风（预览方案 B） |
| dark | 暗色专注 | 深炭灰 + 青绿（预览方案 C） |
| eyecare | 护眼模式 | 豆沙绿底（`#c7edcc`）+ 深绿文字（`#24352a`），配色参考 markdown_reader 的护眼配色 |

实现：三套预览的内联 CSS 合并为 `app.css`，公共规则一份，变量分挂：

```css
:root[data-theme="soft"]    { --bg:…; --primary:…; … }
:root[data-theme="minimal"] { … }
:root[data-theme="dark"]    { …; color-scheme: dark; }
:root[data-theme="eyecare"] { …; color-scheme: light; }
```

四套主题定义的是**同一组变量**（56 个），`tests/themes.test.ts` 会解析 `app.css` 断言变量集合完全一致 —— 漏写一个的话该变量会回落到未定义，页面局部变透明/变黑，这种问题很难靠肉眼发现。

`resolveTheme(theme)`：`theme !== 'auto'` 直接用；`auto` 时读
`matchMedia('(prefers-color-scheme: dark)')`，深色 → `dark`，否则 → `soft`。
页面挂载时解析一次并把结果写入 `<html data-theme>`；当设置值为 auto 时监听该媒体查询的
`change` 事件实时更新（所有已打开页面各自监听）。minimal / eyecare 仅手动可选，不参与系统联动。

护眼模式的三层明度：页面底 `#c7edcc` < 归档卡片 `#d8f0dc` < 普通卡片 `#e8f8ea`，用明度差代替纯白卡片压绿底，避免"白纸贴绿墙"的强反差。

**主题预览页**：`npm run preview` 会读真实的 `app.css` + `app-template.ts` 骨架 + `icons.ts` + zh_CN 文案，生成自包含静态页 `previews/theme-preview.html`，右下角带主题切换条（含 `?theme=dark` 直接打开某套）。刻意不手写 mockup —— 手抄的预览稿会和 `app.css` 悄悄漂移，生成的就一定和真机一致（改完 CSS 重跑一次即可）。

切换 = 改设置 → 重算 data-theme 并持久化，瞬时生效无需刷新。

## 8. 国际化（对应需求第 2 点）

照搬参考项目方案：

- Chrome 标准 `_locales/<locale>/messages.json`（`{key:{message,description}}`，`$1` 占位符）+ `shared/i18n.ts` 的 `t()`，**支持运行时手动切换**（这是不用裸 `chrome.i18n.getMessage` 的原因）
- 回退链：手动语言 → 浏览器语言（auto）→ zh_CN → key 本身
- V1 语言：**简体中文（基准，必须完整）+ English**；加日/韩只需新增 JSON + i18n.ts 登记一行，缺 key 只警告不阻塞（`check-locales.py`）
- JS 中 `t('key')`；HTML 中 `data-i18n / -placeholder / -title`，启动统一填充；切换语言 = setLocale + 重跑 render()
- 扩展商店名称/描述走 `__MSG_extName__`，`default_locale: zh_CN`

**文案范围**：界面所有可见文案（含「未分组」「已完成 N」「已达上限」等）、设置说明；任务数据与用户分组名不翻译。

## 9. 设置面板

设置弹层不另开 options 页，内部**分两个 tab**，打开时默认「基本设置」：

```
基本设置  主题 [跟随系统 ▾]      语言 [跟随浏览器 ▾]
          （主题：跟随系统/柔和明亮/极简专业/暗色专注/护眼模式）
          新建任务位置 [排在最后 ▾]（排在最前 / 排在最后，影响新增与恢复归档）
          自动归档 [开关]
          接管空白标签页 [开关]
          └ 说明文案：关闭后不再接管，新标签页交还浏览器默认页面（已打开的待办页会变成空白提示页）。

高级设置  默认显示条数 [10]        └ 仅影响展示，搜索仍覆盖全部归档
          活跃任务上限 [200]       └ 只限制新增；调小上限不会删除已有任务
          归档容量上限 [500]       └ 调小上限不会立刻删归档，刷新页面后才按新上限裁剪
```

- 分组只在**视图层**：两个 pane 同时在 DOM 里，切 tab 只翻 `hidden` 与 `.active`（不重渲染，输入焦点与未提交的数字不受影响）
- 当前 tab 存在模块级变量里，打开弹层时重置为 `basic`；保存设置会重渲染弹层内容，靠这个变量保持停在原 tab

**自动保存**：任一控件触发 `change` 就立刻保存并生效（下拉/勾选框即时，数字框在失焦或回车提交时），标题下一行写明「改动即时保存，无需确认」；底部按钮只负责关弹层，不存在"忘了点保存"。

- 保存走 `settings-modal.ts` 的 `saveFromForm()`：`readForm()` 读整个表单 → `changeSettings()` 归一化合并 → `applySettingsSideEffects()` 只应用主题/语言并重渲染
- **设置面板不做任何裁剪**：`archiveLimit` 只在页面加载时生效、`activeLimit` 只在新增时拦（见 6.4），所以"改设置"永远不会删数据
- 每次保存都会重渲染弹层内容（主题/语言可能要换文案），因此 `renderSettings()` 在重建前记下 `document.activeElement.id` 并在重建后恢复焦点，键盘操作不中断
- 越界值由 `normalizeSettings` 收敛后回填表单（例如输入 99999 → 存 100，控件显示 100）

设置弹层底部保留构建时间（`__BUILD_TIME__`）便于开发期确认加载版本。

## 10. 页面与组件（渲染模型）

- 单一内存状态 `{settings, groups, tasks, archived, currentGroup, keyword}`；任何操作改 store → 重取状态 → `render()`；与预览稿一致，无虚拟 DOM
- 行内编辑/下拉等瞬态 UI 不受全量 render 影响的处理沿用预览稿方式（编辑时替换为 input，保存后才触发 render）
  - 进入行内编辑有两条路：**双击标题**、点行内的铅笔按钮。两处都主动教这个手势：铅笔的 tooltip 是「双击也可进行编辑」（`opRename`），标题 hover 提示是「双击编辑」（`editHint`）—— 单一入口容易被忽略，所以重复提示一次
- toast 用于：达上限、归档被裁剪提示、恢复成功等
- 空状态：无任务 / 分组下无任务 / 归档搜索无结果
- 拖拽排序用原生 HTML5 DnD（dragstart/dragover/drop 事件委托在 `#taskList` 上）：**行本身绝不可拖**，可拖的只有两处 —— 行左侧手柄 `.grip` 与标题右侧的空白块 `.t-fill`（`flex: 1` 吃满剩余宽度、`align-self: stretch` 撑满行高，不可见但好点中）
  - **为什么不是整行 draggable**：文字必须有可选中/复制的行为，而实测在 Chrome 里「整行 `draggable="true"` + 文字 span 上 `draggable="false"`」和「+ `user-select: text`」**都挡不住起拖**，左键选字会变成拖拽。所以文字外层不能有任何 draggable 祖先 —— 这是唯一确定有效的做法，别改回去
  - 拖拽影像用 `setDragImage(row, …)` 换成整行，所以拖那两块空白时跟手的仍是整行；落点用 `::before/::after` 画指示线
  - 只允许**同一列表内部**重排（跨过「已完成」分隔线不产生落点）：勾选/恢复才是切换列表的唯一入口
  - 分组筛选视图下拖拽只改可见项的相对顺序：`moveTask` 以「落到某行之前」表达落点，隐藏任务顺序不受影响
  - 正在行内编辑的行不响应拖拽（否则重渲染会丢掉未保存的输入）；从行内选中文字往外拖不会触发重排（`dragId` 为空时直接忽略）
  - 触摸设备不支持 HTML5 DnD（桌面浏览器场景）
- 新增行（`app-template.ts` 里位于 `#taskList` **之前**）：任务多到要滚动时，新增入口仍在卡片上方紧挨 Tab，不必滚到底部；`#groupPicker` 放在该行最右
- **进入页面 / 切换分组后自动聚焦新增输入框**（`focusNewTask()`，由 `mount.ts` 与分组 Tab 点击处调用）：新标签页打开、或切到某个分组后即可直接打字；`app.html#settings` 深链时随后由设置弹层把焦点抢过去，不冲突；删分组导致的回落不抢焦点（弹层还开着）
- **归档区默认折叠**：头部（`#archiveHead`）整行是开关（`role="button"` + 键盘 Enter/Space），点搜索框不触发切换；折叠态由卡片上的 `.collapsed` class 驱动 CSS，只隐藏 `.archive-body` / 搜索框 / 「最近 N 条」，头部始终显示 `归档 + 总数` 徽标；展开态记在 `todo:ui:v1`，刷新后保持
- 「全部归档」按钮由 `task-list.ts` 渲染在**已完成分隔行**右侧（分隔行只在当前视图有已完成任务时出现）；它归档的是**所有**已完成任务（含其他分组），所以按钮上的数量单独统计，与左侧 `已完成 N`（当前视图可见数）可能不同；按钮走 `#taskList` 上已有的 `data-act` 事件委托

## 11. 新标签页接管：机制、代价与取舍（重点）

**浏览器限制（Chrome / Edge / Firefox 共同）**：

1. `chrome_url_overrides.newtab` 只能在 manifest 中静态声明，**没有运行时 API 可以取消接管**。
2. 扩展页面无权导航到 `chrome://newtab` / `about:newtab`，因此「开关关闭时跳回原生新标签页」不可行。

**本方案：不做静态覆盖，改由 background 运行时重定向。**

```
新标签页事件（tabs.onCreated / tabs.onUpdated）
  └─ 地址是原生新标签页（shared/newtab-url.ts 识别 chrome: / edge: / brave: / about: …）
       ├─ newtabOverride = true  → chrome.tabs.update(tabId, build/newtab.html)
       └─ newtabOverride = false → 什么都不做（浏览器原生页留着）
```

- 开关成为**真开关**：关闭后新标签页就是浏览器原生页面，扩展不再需要「已关闭」占位态
- 扩展自己的新标签页页面**只有一种形态**：任何落到 `build/newtab.html` 的标签页都渲染 Todo（直接打开、开关刚被关掉、被重定向过来都算），视图分流与停用页一并删除
- 地址识别是纯函数，放 `src/shared/newtab-url.ts`，node 下可测（`tests/newtab.test.ts` 覆盖各家 scheme 与误判）
- 开关值在 background 里做内存缓存（首次事件读一次 storage，之后由 `storage.onChanged` 维护），热路径上不同步等 storage
- Edge / Firefox 同机制，无平台分支（`about:newtab` / `about:home` 一并识别）

**代价（必须对用户诚实）：**

| 代价 | 说明 |
|---|---|
| `tabs` 权限 | 读标签页地址必须申请，安装/更新提示为「读取您的浏览记录」 |
| 闪帧 | 重定向发生在原生页提交之后；后台脚本冷启动（浏览器刚打开）时更明显 |
| 地址栏与历史 | 重定向是普通导航：地址栏显示扩展地址，新标签页会留下一条后退记录 |
| 抢焦点 | Ctrl+T 后立即输入时，重定向导航可能抢走地址栏焦点（概率极低） |

## 12. 图标与资源

- `icons/source.svg` 一个源图：**品牌蓝实心圆 + 白色对勾**（`#4d6bfa` 圆，`r = 58.67/128`；对勾为 13.87 宽、圆头线帽的折线），`make-icons.py` 用 Pillow 画同款几何生成 16/32/48/128 PNG（`uv run --with Pillow scripts/make-icons.py`，遵循本机 Python 走 uv 的约定）。这四个 PNG 只用于工具栏、扩展管理页、商店与安装弹窗
  - 造型参照主流待办应用（Things / Apple 提醒 / Google Tasks / TickTick）：**一个圈里一个勾**，扁平、无渐变、无阴影 —— 因为 Chrome 工具栏在深浅主题下的底色不同而扩展图标不会自动反色，实心块比细描边（尤其深墨色描边）在两种底色下都稳；16px 下也只剩"圆 + 勾"两个形状，不会像旧版那样挤在一起
  - 候选对比页留在 `previews/icon-candidates.html`（7 个候选 + 旧版，各自渲染 128/64/32/16 三种底色），改图标时可以重开它选型
  - SVG 与 Pillow 是两份独立实现（刻意不依赖 SVG 栅格器），改几何时两边都要改；可用 headless Chrome 渲染 SVG 与生成的 PNG 逐像素比对来验证一致性（本次 128px 下差异 0.02%，仅圆边抗锯齿）
- **页面顶栏不放图标，只有标题文字**（`<div class="brand"><span data-i18n="appTitle"></span></div>`）：品牌位保持干净；早先用 `✦` 字符占位、与真实图标对不上，试过直接引用 `icons/128.png`，结论是干脆留空白版式更清爽
- 无自定义字体、无外部网络请求（扩展完全离线工作）

## 14. 风险与限制

| 风险 | 说明 / 缓解 |
|---|---|
| Firefox MV2 生命周期 | Mozilla 仍接受 MV2 加载/上架（≥128）；与参考项目相同策略，未来 MV3 迁移只需在 manifest.mjs 加目标 |
| 全量 render 性能 | 上限内（千条级）无压力；archiveVisible 控制默认渲染数；搜索结果如过大再加分批（V1 不做） |
| storage.local 写放大 | 每次操作全量覆盖保存；千条任务、每条几十字节，量级远低于 local 的 10MB 配额 |
| 新标签页接管需要 `tabs` 权限 | 第 11 节已述：用运行时重定向换取「关掉即交还原生页」，代价是权限提示、可能的闪帧、地址栏可见扩展地址 |
| 非 ASCII 构建 | build.mjs 的 ASCII 兜底插件直接照搬 |

## 15. 决策记录（2026-10-12 已确认）

1. 容量默认值：**活跃 50 / 归档 100 / 默认显示 10**；范围保持 20–1000、50–5000、1–100。
2. 设置与数据统一用 **chrome.storage.local**，不做跨设备同步。
3. 归档分组名采用**归档瞬间快照**，之后分组改名/删除不影响旧归档显示。
4. （修订）新标签页接管改为**运行时重定向**（不声明 `chrome_url_overrides`），让「关闭接管」真正交还浏览器原生新标签页；接受 `tabs` 权限与可能的闪帧（见第 11 节）。
5. 新标签页接管**默认开启**（`newtabOverride: true`）。
6. V1 语言：**zh_CN（基准）+ en**。
7. 主题：soft / minimal / dark 三套 + **「跟随系统」auto（默认项）**，auto 在浅/深系统下分别对应 soft / dark；后续增补 **eyecare 护眼模式**（豆沙绿，手动可选，不参与系统联动）。
